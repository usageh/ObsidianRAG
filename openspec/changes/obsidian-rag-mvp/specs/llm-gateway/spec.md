## Purpose

统一封装对话、视觉、嵌入三类大模型调用渠道与全局配置，供其他能力复用，避免每个能力各自管理模型访问。

## ADDED Requirements

### Requirement: 单一渠道访问三类模型

系统 SHALL 通过统一的 base_url 与单个 API key 环境变量访问对话、视觉、嵌入三类模型；各类模型的 model id SHALL 可在配置中独立设置与替换。

#### Scenario: 配置缺失时拒绝启动

- **WHEN** 启动时 API key 环境变量未设置
- **THEN** 系统明确报错指出缺失的变量名并停止启动，不进入服务态

#### Scenario: 切换模型 id

- **WHEN** 配置中将视觉模型 id 改为另一个支持的 id
- **THEN** 系统后续视觉调用使用新 id，无需改动其他能力

### Requirement: 嵌入接口

系统 SHALL 接受文本输入并返回固定维度的浮点向量，维度在配置生效期间保持恒定。

#### Scenario: 文本转向量

- **WHEN** 调用嵌入接口传入一段文本
- **THEN** 返回与配置维度一致的向量

### Requirement: 视觉接口

系统 SHALL 接受图片（本地文件路径或 base64）加文本提示，返回模型生成的文本（用于 OCR 与图片理解）。

#### Scenario: 截图 OCR

- **WHEN** 传入一张截图与提示词"提取图中所有文字"
- **THEN** 返回图中可识别的文字内容

### Requirement: 对话接口

系统 SHALL 接受消息序列并返回文本生成结果，供问答、巩固出题、摘要等场景复用。

#### Scenario: 问答生成

- **WHEN** 传入包含检索上下文与用户问题的消息序列
- **THEN** 返回基于上下文的回答文本
